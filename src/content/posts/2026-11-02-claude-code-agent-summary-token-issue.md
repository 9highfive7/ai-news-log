## ポイント

- エージェントの要約処理が全トークンの約15〜20％を消費している
- 一定間隔で会話データをモデルに送り直して状態を更新している仕様になっている
- Bunを用いた回避策が提案されているが、導入リスクを懸念する声もある

## 要約

Flamerix AIによるOpenTelemetryの分析で、Claude Codeのエージェントサマリー機能がトークン全体の約15〜20％を占有していることが判明した。稼働中のエージェントの状態を半 minuto 単位で同期させるため、全会話データをモデルへ送り直して短い要約を取得している仕組みに原因がある。特にOpusモデルを使用する環境では消費割合がさらに高まり、API通信のおよそ5回に1回がこの処理に費やされている。

これに対処するため、Flamerix AIはBunのプリロード機能を利用して該当するタイマー処理だけを停止させる回避策を提示した。製品の実行ファイルを直接書き換えない仕組みであるものの、仕様変更に伴うリスクや環境変数への影響を懸念して導入を見送るべきだとする指摘も存在する。さらに、Opusモデルの利用時にユーザーのメールアドレスがリクエストヘッダーへ露出する別の不具合も確認されている。
